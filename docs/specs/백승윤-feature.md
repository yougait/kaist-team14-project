## 한 줄 요약

부스에서 측정한 러너에게 **케이던스 기준으로 바꿀 행동 딱 하나**를 제안하고, 3분 연습 뒤 **같은 조건에서 재측정한 값과 비교**해 행동이 실제로 바뀌었는지 보여 주는 태블릿 화면. 실제 센서 데이터는 아직 검증되지 않았으므로 **데모 데이터**로만 보여 준다.

## 연결된 문제 (WhyTree)

- **C. 실제로 자세를 바꾼다**
  - **C3.** 가장 중요한 교정 행동 하나만 제안 → 카드는 행동 1개만 보여 준다.
  - **C4.** 같은 조건에서 재측정해 변화 확인 → 조건 체크 뒤 전후를 비교한다.
- 출발점: 내 프리모텀 #2 "AI의 교정 제안이 고객의 행동 변화로 연결되지 못했다" (원인: 한 번에 여러 교정을 제안했고, 재측정으로 확인하지 않았다).

## 대상과 사용 상황

- **대상:** 부상 없이 오래 달리고 싶은 30대 사무직 러너
- **상황:** 마라톤 행사 부스에서 니치로 측정한 직후, 태블릿으로 결과를 본다. 같은 방문 안에서 3분 연습과 재측정까지 마친다.

## 사용자 흐름

1. 1차 측정 결과(케이던스, 측정 시간)를 본다.
2. 행동 카드 1장을 본다: 무엇을 / 왜 이것 하나만 / 어떻게 확인하나.
3. 목표 박자로 3분 달린다 (P1: 화면의 메트로놈 사용).
4. 재측정 전 조건 3가지(같은 신발, 같은 코스, 비슷한 속도)를 체크한다.
5. 재측정 결과를 1차값·목표값과 나란히 본다.

## 원칙

1. **행동은 하나만.** 한 화면에 교정 행동을 두 개 이상 쓰지 않는다.
2. **근거가 부족하면 제안하지 않는다.** 기준을 못 넘으면 "제안하지 않음"을 보여 준다.
3. **조건이 다르면 비교하지 않는다.** 체크가 하나라도 빠지면 전후 비교를 숨긴다.
4. **판단하지 않는다.** 좋음/나쁨 색, 점수, 등급을 쓰지 않는다. 변화는 중립 문장으로만 쓴다.
5. **의학적 주장을 하지 않는다.** 부상·통증·진단 표현을 쓰지 않고 「의학적 진단이 아닙니다」를 표시한다.
6. **데모임을 숨기지 않는다.** 「데모 데이터」 배지를 항상 표시한다.

## 제안 규칙 (규칙 기반, AI 호출 없음)

| 조건 | 화면 |
|---|---|
| 측정 시간 < 120초 | "데이터가 부족해 이번에는 제안하지 않아요." |
| 측정 시간 ≥ 120초, 케이던스 < 170 spm | 행동 카드: "다음 러닝에서 박자를 {현재} → {round(현재×1.05)} spm으로" |
| 측정 시간 ≥ 120초, 케이던스 ≥ 170 spm | "지금 박자를 유지하세요. 이번에는 바꿀 행동이 없어요." |

- 170 spm과 +5%는 **데모용 기준**이며 화면에 "데모 기준 · 개인차 있음"을 표시한다.

## AI 모델과 실패 시 처리

- **P0:** AI를 쓰지 않는다. 위 규칙으로만 행동을 고른다. 공개 레포의 웹페이지에 API 키를 넣으면 키가 공개되므로 브라우저에서 AI를 호출하지 않는다.
- **P2:** 서버를 두고 Claude Haiku 5.5로 카드의 "왜" 문장을 러너 상황에 맞춰 쉬운 말로 다시 쓴다. AI 호출이 실패하거나 3초 안에 답이 없으면 **규칙 기반 기본 문구**를 그대로 보여 준다. AI는 행동을 고르지 않고 문장만 다듬는다.

## 요구사항

### P0 — 반드시 구현

| ID | 요구사항 |
|---|---|
| P0-1 | 1차 측정값(케이던스 spm, 측정 시간)을 표시한다. |
| P0-2 | 제안 규칙 표에 따라 행동 카드 / 바꿀 행동 없음 / 데이터 부족 중 하나만 표시한다. |
| P0-3 | 행동 카드는 세 줄로 구성한다: ① 무엇을 ② 왜 이것 하나만 ③ 어떻게 확인하나 |
| P0-4 | 재측정 전 조건 체크리스트 3개(같은 신발, 같은 코스, 비슷한 속도)를 표시한다. |
| P0-5 | 셋 다 체크하면 1차값·재측정값·목표값을 나란히 보여 주고 "목표 쪽으로 +N spm 움직였어요"처럼 중립 문장 하나를 표시한다. |
| P0-5a | 재측정값이 목표에서 더 멀어졌으면 "목표 반대쪽으로 -N spm 움직였어요"처럼 같은 형식의 중립 문장을 쓴다. (구현 중 추가) |
| P0-6 | 하나라도 체크하지 않으면 비교 대신 "조건이 달라 비교하지 않아요."를 표시한다. |
| P0-6a | 체크리스트가 모두 비어 있는 첫 상태에서는 "위 세 가지를 확인하면 비교를 보여 드려요."를 표시한다. 아직 아무것도 하지 않았는데 "비교하지 않아요"가 보이면 오류처럼 읽힌다. (구현 중 추가) |
| P0-7 | 「데모 데이터」 배지와 「의학적 진단이 아닙니다」 문구를 항상 표시한다. |
| P0-8 | 데모 데이터는 HTML 상단의 `DEMO_DATA` 객체로 분리해 화면 코드를 고치지 않고 값을 바꿀 수 있다. |
| P0-9 | 빌드 없이 파일을 열면 실행되고, 외부 라이브러리와 네트워크 요청이 없다. |
| P0-10 | 휴대폰 너비(360px)부터 태블릿까지 가로 스크롤 없이 보인다. |

### P1 — 시간이 되면

| ID | 요구사항 |
|---|---|
| P1-1 | 카드의 메트로놈 버튼을 누르면 목표 spm 박자로 소리가 나고, 다시 누르면 멈춘다. |
| P1-2 | 시스템 설정에 따라 라이트·다크 모드를 지원한다. |
| P1-3 | 버튼과 체크박스는 키보드만으로 쓸 수 있다. |

### P2 — 나중에

| ID | 요구사항 |
|---|---|
| P2-1 | 실제 KNEECH 센서 데이터 연동 (`DEMO_DATA` 자리를 실제 값으로 교체) |
| P2-2 | Claude Haiku 5.5로 "왜" 문장 개인화 (실패 시 규칙 문구) |
| P2-3 | 다음 러닝 직전 리마인드 (WhyTree C5) |

### 하지 않는 것

- 여러 지표를 동시에 교정하기, 좋음/나쁨 평가, 의학적 판단
- 데이터 저장·전송, 로그인
- 영어 등 다른 언어 지원

## 수동 테스트

브라우저에서 `prototypes/백승윤/index.html`을 직접 열고 확인한다.

| # | 확인 방법 | 통과 기준 | 관련 |
|---|---|---|---|
| T1 | 기본 데모값(160 spm, 150초)으로 연다. | 카드에 "160 → 168 spm" 행동 하나와 세 줄(무엇을/왜/확인)이 보이고, 콘솔 오류가 없다. | P0-1~3, P0-9 |
| T2 | `DEMO_DATA.first.cadence`를 175로 바꾸고 새로고침한다. 다음에 `durationSec`을 90으로 바꾼다. | 175면 "바꿀 행동이 없어요", 90초면 "데이터가 부족해 … 제안하지 않아요"가 나오고 카드는 사라진다. | P0-2, P0-8 |
| T3 | 처음 상태를 본다. 하나만 켠다. 셋 다 켠다. | 처음에는 "위 세 가지를 확인하면 …", 일부만 켜면 "조건이 달라 비교하지 않아요", 셋 다 켜면 160 / 166 / 168과 "목표 쪽으로 +6 spm 움직였어요"가 보인다. | P0-4~6a |

## 검증 (사용자 인터뷰)

부스 인터뷰에서 진행자가 묻고 기록한다. 아직 실제 사용자 테스트는 하지 않았다.

- 카드를 본 뒤, 다음 러닝에서 바꿀 행동을 자기 말로 설명할 수 있는가? (팀 기준: 20명 중 10명 이상)
- 재측정 비교를 보고 "바뀌었다/안 바뀌었다"를 스스로 말할 수 있는가?
